# Mermaid 架构图与时序图规范

本章涉及架构与流程表达时，必须遵守以下规范：

## 架构图（graph TD）
- 使用 `graph TD` 自顶向下分层表达，推荐分层（按主题裁剪）：
  - 接入层：DNS / LB / Gateway
  - 服务层：业务服务、中间件、调度组件
  - 存储层：数据库、缓存、对象存储、消息队列
  - 基础设施层：机房 / 可用区 / K8s / 监控
- 用 `subgraph` 表达分层，同层节点放在同一个 subgraph 内。
- 箭头标注关键协议或语义，如 `A -->|HTTPS| B`、`C -.->|异步消费| D`。

## 时序图（sequenceDiagram）
- 核心调用链（如一次请求的完整路径、一次故障切换过程）用 `sequenceDiagram` 表达。
- participant 用有意义的名称，消息标注关键操作和返回值。

## 书写细节
- 节点名避免特殊字符：不使用空格、括号、斜杠等；需要展示中文名称时用引号包裹，如 `A["用户服务"]`。
- 中文标签一律用引号包裹，避免渲染失败。
- 图不宜过大：一张图聚焦一个视角，节点超过 15 个就拆分。

## 数量与解读
- 每个架构类章节（总体架构、详细设计、核心流程）至少包含 1 张 Mermaid 图。
- 每张图之后必须紧跟一段文字解读：说明图的视角、关键节点职责、数据流向，禁止只放图不解释。
