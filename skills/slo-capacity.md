# 容量评估与 SLO 写法

本章涉及容量规划或服务质量目标时，必须按以下结构写作：

## 容量估算
- 先列出**估算假设**（用列表逐条给出）：日活、人均请求数、峰值系数、数据增长率等，假设必须给出具体数值和依据；依据不明的标注（待验证）。
- 再给出估算公式与结果，常用口径：
  - QPS：日均 QPS = 日活 × 人均请求数 ÷ 86400；峰值 QPS = 日均 QPS × 峰值系数（通常取 3-10，需说明取值理由）。
  - 存储：单条记录大小 × 日增量 × 保留天数 × 副本数 × 膨胀系数（索引/WAL，通常 1.3-2）。
  - 带宽：峰值 QPS × 单请求平均响应大小，注意区分出入口带宽。
- 估算结果用表格汇总，并给出机器/实例数量结论（配置规格 + 数量 + 冗余系数）。

## SLO 指标表
必须使用 Markdown 表格给出 SLO：

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 可用性 | 如 99.95% | 统计口径与排除项 |
| P99 延迟 | 如 < 500ms | 统计窗口与范围 |
| RTO | 如 < 30min | 故障恢复时间目标 |
| RPO | 如 < 5min | 数据丢失容忍目标 |

- 每个指标必须说明统计口径（窗口、采样范围、排除计划内维护等）。
- 目标值必须可测量，禁止「高性能」「高可用」这类无量化表述。
- 如与行业基准或既有系统对齐，注明来源 `[来源: URL]`。
