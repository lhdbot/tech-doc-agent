# Markdown 写作硬性规范

本章输出必须满足以下 Markdown 规范，逐条检查后方可交付：

## 标题
- 章节标题从 `##` 开始（一级标题 `#` 由文档总编统一生成，禁止自行使用）。
- 标题层级必须连续，禁止跳级：`##` 之后是 `###`，`###` 之后是 `####`。
- 标题写具体内容（如「### 分片键选择与路由策略」），禁止空泛标题（如「### 设计说明」）。

## 代码块
- 所有围栏代码块必须标注语言：```` ```python ````、```` ```bash ````、```` ```yaml ````、```` ```json ````、```` ```sql ```` 等。
- 伪代码统一使用 ```` ```pseudo ````；架构图统一使用 ```` ```mermaid ````。
- 代码块内的配置、命令、参数必须是真实可用的，禁止占位符式的伪配置（如 `your_password_here` 出现在非示例语境中需说明）。

## 表格
- 方案对比、参数清单、指标汇总一律使用 Markdown 表格，不要用大段文字罗列。
- 表格必须有表头行，列数与分隔行一致；单元格内容保持简短。

## 事实性论断
- 涉及版本特性、性能数据、价格、API 行为等事实性论断，句末必须标注来源，格式：`[来源: URL]`。
- 无法核实来源的论断，句末标注 `（待验证）`，禁止编造数据或来源。

## 语言风格
- 中文写作，技术术语保留英文（如 QPS、failover、TTL）。
- 禁止空话套话：不出现「众所周知」「随着互联网的飞速发展」「综上所述非常重要」等无信息量句子。
- 每句话都要携带信息：要么是事实，要么是决策，要么是操作步骤。
