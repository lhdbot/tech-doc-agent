# 方案对比与选型决策写法（ADR）

本章涉及技术选型或方案对比时，必须按以下结构写作：

## 候选方案
- 列出 2-4 个真实可行的候选方案（自研、开源组件、云服务等），每个方案一句话定位。
- 禁止设置明显凑数的稻草人方案。

## 对比表
必须使用 Markdown 表格对比候选方案，维度至少覆盖：

| 维度 | 方案A | 方案B | 方案C |
| --- | --- | --- | --- |
| 一致性 | | | |
| 可用性 | | | |
| 成本 | | | |
| 复杂度 | | | |
| 生态 | | | |

- 一致性：强一致 / 最终一致 / 会话一致等。
- 可用性：单点风险、多副本能力、故障切换时间。
- 成本：License、云服务费用、人力投入（量级即可）。
- 复杂度：部署、运维、接入改造成本。
- 生态：社区活跃度、文档质量、上下游集成能力。

## 决策结论
- 表格之后必须明确给出推荐结论：「推荐方案X」，并说明理由。
- 理由必须结合本项目的具体约束（团队规模、现有技术栈、量级、SLA 要求），禁止只罗列通用优缺点。
- 说明被放弃方案的适用边界：什么情况下应该重新评估（例如「当日活超过 X 或团队扩充到 Y 人时，重新评估方案B」）。

## 决策记录
- 如适用，可附一行决策记录格式：决策点 / 结论 / 决策人 / 日期（决策人与日期可标注（待确认））。
